🔄 FLUJOS DE PROCESOS DOCUMENTADOS
─────────────────────────────────────────────────────────────────

1️⃣  REGISTRO DE USUARIO
   Usuario → Página /register → POST /api/auth/register 
   → Backend valida → Encripta contraseña → Emite JWT 
   → Guarda en localStorage → Usuario logueado

2️⃣  LOGIN DE USUARIO
   Usuario → Página /login → POST /api/auth/login 
   → Backend verifica credenciales → Emite JWT 
   → localStorage guarda token → Acceso a funciones protegidas

3️⃣  VER PRODUCTOS
   Usuario → /productos → productsLoader ejecuta 
   → GET /api/products → Backend retorna lista 
   → Componente renderiza grid → Usuario ve catálogo

4️⃣  AGREGAR AL CARRITO
   Usuario clica "Agregar" → useCart().addToCart() 
   → CartContext actualiza estado → localStorage guarda 
   → Contador en header actualiza

5️⃣  COMPRA COMPLETA
   Usuario clica "Pagar" → CheckoutForm abre → Usuario completa datos 
   → POST /api/sales/init → Backend valida stock 
   → Contacta Transbank → Retorna token y URL 
   → Frontend redirige a Transbank → Usuario ingresa tarjeta 
   → Transbank aprueba → Redirige a /checkout-success 
   → Frontend POST /api/sales/commit → Backend confirma 
   → Stock actualiza → ✓ Compra completada

🛡️  SEGURIDAD EXPLICADA
─────────────────────────────────────────────────────────────────

✅ Encriptación de Contraseñas
   Utilizamos BCrypt. Las contraseñas NUNCA se guardan en texto plano.
   Cuando usuario se loguea, contraseña ingresada se compara con hash.

✅ JWT (JSON Web Tokens)
   Sistema seguro donde backend emite token firmado.
   Cada request incluye token en header Authorization.
   Token contiene identidad del usuario y expira después de 24 horas.

✅ Validación en Múltiples Capas
   Frontend: Valida para UX (email formato, contraseña fuerte)
   Backend: Valida por seguridad (nunca confiar en cliente)
   BD: Constraints validan integridad (UNIQUE, FK, NOT NULL)

✅ CORS Configurado
   Todos endpoints tienen @CrossOrigin(origins = "*")
   En producción: Restringir a dominio específico

✅ Datos en localStorage
   Solo se guarda: token JWT, carrito (datos públicos)
   NO se guarda: contraseña, datos sensibles

💡 CONCEPTOS CLAVE EXPLICADOS
─────────────────────────────────────────────────────────────────

🔹 MICROSERVICIOS
   Arquitectura donde cada función está en servicio independiente.
   • Cada uno tiene su BD
   • Se comunican por HTTP/REST
   • Escalan independientemente
   • Fallos aislados

🔹 CONTEXT API
   Sistema React para estado global sin pasar props.
   • AuthContext para usuario
   • CartContext para carrito
   • Evita "prop drilling"

🔹 REACT ROUTER
   Gestiona rutas en SPA (sin recargar página).
   • Loaders cargan datos antes de renderizar
   • useParams para extraer parámetros
   • Navegación smooth

🔹 DTOs (Data Transfer Objects)
   Objetos SOLO para transferir datos entre capas.
   • Separan modelo de BD del API
   • Evitan exponer estructura interna
   • Validación centralizada

🔹 JWT (JSON Web Tokens)
   Tokens firmados digitalmente para autenticación.
   • Sin necesidad de sesiones en servidor
   • Cliente envía token en cada request
   • Expiran automáticamente

🔹 REPOSITORY PATTERN
   Abstrae acceso a datos.
   • En lugar de escribir SQL: findByCodigo(codigo)
   • Spring Data JPA genera SQL automáticamente
   • Código más legible y mantenible
